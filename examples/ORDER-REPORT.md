# 固定订单报表示例（合成数据）

此示例用于理解合同和验收，没有在本公开版本中执行，不是历史测试数据或新的性能成绩。

## 输入

UTF-8 CSV，字段固定；保留每行和前导零，重复订单号不等于重复行，不擅自去重。`amount_cents`为有符号整数分，`quantity`为非负整数；行金额＝单价分×数量。负单价在本示例表示退款。

```csv
row_id,order_id,customer,amount_cents,quantity
001,0007,Alpha,1200,2
002,0007,Alpha,-300,1
003,0008,Beta,500,0
004,0009,alpha,250,3
```

## 交付合同

- `details.csv`：保留4行原字段及行顺序，追加`line_total_cents`。
- `summary.json`：记录行数、数量总计、金额总计及按客户精确区分大小写的汇总。
- 成功时提供成品和独立验收回执；有非法整数、缺字段、空客户名或负数量时明确拒绝并指出输入行，不提交成品。
- 仅处理这份合成数据，不发邮件、不收款、不写入外部业务系统。

## 预期结果

| 项目 | 预期 |
| --- | --- |
| 行数 | 4 |
| 行金额（分） | 2400、-300、0、750 |
| 数量合计 | 6 |
| 金额合计（分） | 2850 |
| Alpha汇总（分） | 2100 |
| Beta汇总（分） | 0 |
| alpha汇总（分） | 750 |

独立检查必须从原始输入重算，验证四行均保留、`001`及`0007`仍为文本、退款符号正确、零数量不丢行及大小写客户不合并。不能只检查文件存在。

## 故障接续判断

- 生成前退出：确认旧进程停止、输入身份一致并取得执行权后，继续生成。
- 成品已确认后退出：核对原产物身份，继承成品，只补验收/提交。
- 已提交且回执可确认：只读返回原结果，不再生成或提交。
- 未知部分写入、锁未释放或无法确认旧进程状态：保留证据并停止对账。

现实故障验收需要已有执行器、检查点和受控故障注入；这些文字不等于系统具备了自动恢复能力。
